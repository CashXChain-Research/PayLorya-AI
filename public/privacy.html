5. Wallets, keys and financial connections

Agent-wallet custody: if you connect an agent wallet by recovery phrase, the server receives the phrase, encrypts it at rest using AES-256-GCM with a key derived from the application's server secret, and decrypts it when needed to sign. This is a server-held signing key, not a browser-only or non-custodial connection. Use a separate Cardano Preprod wallet with test tADA only. CashXChain API keys are also encrypted at rest and bound to your workspace. Encryption does not prevent the running service from using a connected credential for the functions you permit.

Browser wallets: a Cardano wallet connected through CIP-30 can sign a payout in its own dialog. We receive the address, transaction/UTxO data and the returned signature, not its recovery phrase. EVM connections read public addresses and balances. Stripe Financial Connections uses Stripe's own bank-linking dialog; we receive connection identifiers, institution/account metadata, last four digits and balances. We do not receive the bank login credentials. This connection is read-only.

Blockfrost receives blockchain queries and transactions; public EVM RPC providers receive address and balance queries. CashXChain receives account, beneficiary and payment information for sandbox operations. Public blockchain addresses, amounts and transactions are visible to others and cannot generally be erased.
